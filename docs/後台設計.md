# 後台內容模型設計

> 2026-09-20 草案　·　待資訊總監確認
> 對應架構：Astro（前台）＋ Sanity（後台）＋ Cloudflare Workers（託管）

---

## 一、設計目標

同事要能自己改內容，但**改不壞版型**。這條線畫在哪，決定了你之後多常被找。

| | 同事自己改 | 需要改程式 |
|---|---|---|
| 文字、日期、圖片 | ✅ | |
| 新增／刪除／排序條目（一篇文章、一場活動、一位理事） | ✅ | |
| 草稿、預覽、發布、下架 | ✅ | |
| 版型、配色、字體、導覽列結構 | | ✅ |
| **新增一種內容類型**（例如「課程」） | | ✅ |

最後一列是最常見的回頭找人原因。所以下面的模型刻意把**欄位設寬一點**——寧可多一個選填欄位，不要三個月後為了加一個欄位改程式。

---

## 二、安全設計（不可妥協）

1. **不提供任何「檔案／附件」欄位，只給圖片欄位。**
   同事誤傳 `會員名冊.xlsx` 的唯一有效防線，是讓那個動作在介面上不存在。
   刪除是最後一道防線不是第一道——Sanity 的 CDN 快取在資產轉為私有後最長可能續供 30 天。

2. **必須使用非營利方案或 Growth，不能用免費方案。**
   免費方案的 dataset 只能是公開的，未發布的草稿會被匿名 API 讀走。

3. **同事給 Editor 角色，不給 Administrator。**

4. **理監事文件、會員名冊、會議紀錄一律不進這個系統**，它們的家是 Google 共用雲端硬碟。

## 三、文件類型

### A. 集合型（有很多筆）

#### 1. `article` 專欄文章 ★最重要
目前有 2 篇，之後每月新增。

| 欄位 | 型別 | 說明 |
|---|---|---|
| 標題 | 字串 | 必填 |
| 網址代稱 slug | slug | 由標題自動產生，可手改。決定 `/column/xxx` |
| 分類 | 單選 | 身心健康／藝術陪伴／生態永續／慢旅共學／其他 |
| 系列名稱 | 字串 | 選填。例：`慢活文字專欄｜每月一味` |
| 摘要 | 文字 | 列表頁與搜尋結果會顯示，也是 SEO description |
| 封面圖 | 圖片 | 含替代文字（無障礙＋SEO） |
| 作者 | 參照 `author` | |
| 發布日期 | 日期 | |
| 標籤 | 字串陣列 | |
| 內文 | 富文本 | 段落、小標、粗體、連結、清單、插圖、強調區塊 |
| 相關連結 | 物件陣列 | 標題＋網址。例：作者的 FB 粉專 |
| 色調 | 單選 | 沙綠／大地／天空。決定卡片邊框與按鈕顏色 |

> **設計說明**：原本兩篇文章的內文格式不同——一篇是保留斷行的詩體，一篇是分段論述。富文本要支援「保留換行的段落」這種區塊，否則茶樹那篇會被壓成一整團。

#### 2. `author` 作者
| 欄位 | 說明 |
|---|---|
| 姓名 | 例：郭純嵐（小嵐老師） |
| 稱銜 | 例：臺灣慢活教育學會創會會員 |
| 頭像字 | 一個字，顯示在圓形色塊裡。留空則取姓名第一個字 |
| 代表色 | 沙綠／大地／天空 |
| 簡介 | 選填，之後若做作者頁會用到 |

#### 3. `person` 理監事與成員
目前 17 位。每屆改選都要整批更新，所以必須好改。

| 欄位 | 說明 |
|---|---|
| 姓名 | |
| 職稱 | 例：理事長、監事、財務顧問 |
| 分組 | 理事／監事／行政秘書處／顧問 |
| 排序 | 數字，小的在前 |
| 備註 | 選填。例：`李臺鴒會計稅務記帳士事務所` |
| 屆別 | 數字，預設 1。**之後換屆時可以只切換顯示哪一屆，舊資料不用刪** |

#### 4. `event` 活動資訊
首頁的跑馬燈與活動卡片。

| 欄位 | 說明 |
|---|---|
| 標題 | 例：苗栗青年藝術論壇 |
| 日期顯示文字 | 自由字串，因為有「2026 · Q3（籌備中）」這種非日期格式 |
| 排序用日期 | 日期，供排序，不顯示 |
| 圖示 | 一個 emoji |
| 說明 | 文字 |
| 分類標籤 | 例：藝術陪伴、慢旅共學 |
| 顯示在跑馬燈 | 是／否 |
| 顯示在活動卡片 | 是／否 |

> **設計說明**：跑馬燈和卡片目前是兩份重複的文字，同事改了一邊忘了另一邊就會不一致。合成同一筆資料、用兩個開關控制在哪裡出現。

#### 5. `planItem` 年度計畫項目
目前 16 項，分屬四個主軸。

| 欄位 | 說明 |
|---|---|
| 所屬主軸 | 會務運作／業務發展／專案計畫／財務規劃 |
| 圖示 | 一個 emoji |
| 標題 | 例：立案與法人登記 |
| 說明 | 文字 |
| 排序 | 數字 |
| 年度 | 例：115、116。**之後可以按年度篩選，舊計畫留存不刪** |

### B. 單例型（全站只有一份）

#### 6. `siteSettings` 網站設定
| 欄位 | 說明 |
|---|---|
| 學會名稱／英文名稱 | 頁尾與結構化資料 |
| 地址、Email | 頁尾與聯絡頁共用一份，改一次全站生效 |
| 立案字號、統一編號 | **立案完成後要填**，目前頁面上是「待公告」 |
| 預設分享圖 | 社群分享用的 1200×630 |

#### 7. `homePage` 首頁
| 欄位 | 說明 |
|---|---|
| Hero 上方小字 | 例：`Est. 2026 · 臺灣` |
| Hero 主標／強調字／英文副標 | 「在學習中找到**慢活**的節奏與喜悅」 |
| Hero 引言 | 三行那段 |
| 主題標籤 | 身心健康／藝術陪伴／生態永續 |
| 關於學會 | 富文本，含可強調的關鍵詞 |
| 活動區塊標題 | |

#### 8. `themesSection` 三大共學主題 ⚠️
**這一塊目前不存在。** 導覽列有「三大共學主題」這個選項，但它指向的區塊從第一版就沒做出來（CSS 寫好了，HTML 從來沒有），按下去什麼都不會發生。

| 欄位 | 說明 |
|---|---|
| 區塊標題／引言 | |
| 主題 ×3 | 名稱、說明、圖示、色調 |

做出來就順便修掉那個壞掉的選單連結。

#### 9~12. 各頁文案
`plansPage`（年度計畫引言與四段主軸導語）、`donatePage`（捐款用途、匯款資訊、收據說明）、`contactPage`、`boardAreaPage`（雲端硬碟連結與說明）。

> **`donatePage` 特別註記**：匯款的銀行與帳號目前是「待立案後公告」。
> ⚠️ **把真實帳號填進去之前，先確認《公益勸募條例》的勸募許可字號。** 這個提醒要直接寫在該欄位的說明文字裡，讓填的人看得到。

## 四、後台選單結構

同事打開後台看到的左側選單，直接對應他們腦中的分類，不是資料庫結構：

```
📝 內容
   ├─ 專欄文章
   ├─ 作者
   ├─ 活動資訊
   └─ 年度計畫項目

👥 組織
   └─ 理監事與成員

📄 頁面文案
   ├─ 首頁
   ├─ 三大共學主題
   ├─ 年度計畫（頁面文字）
   ├─ 捐款支持
   ├─ 聯絡我們
   └─ 理監事專區

⚙️ 網站設定
```

## 五、待你決定

1. **「三大共學主題」要做出來嗎？** 做的話我需要那三個主題各自的說明文字，或授權我從現有文案改寫草稿。若不做，我就把導覽列那個壞掉的選項移除。

2. **專欄以後會有多少作者？** 目前 2 位。如果會長期擴充，值得做作者頁（`/column/author/xxx`），對 SEO 也有幫助。

3. **活動資訊需要獨立頁面嗎？** 目前只在首頁。如果之後會累積很多場、需要報名資訊或回顧，就值得給它 `/events` 和各自的網址。

4. **誰會是編輯？** 需要他們的 Email 來開帳號，也決定要買幾個席次（唯讀的人免費）。

5. **要不要「課程」這個類型？** 你提過業務資料裡有學員與報價。如果之後網站要公開課程資訊（不含報名收費），現在一起設計比之後追加省事。
