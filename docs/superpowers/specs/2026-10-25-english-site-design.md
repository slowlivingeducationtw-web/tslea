# 英文版網站設計（多語言架構，先開英文）

日期：2026-10-25　｜　需求來源：學會資訊總監　｜　狀態：待核可

## 1. 目的與原因

學會成員到國際交流、或外國人來台交流時，需要一個網址就能把學會完整介紹給對方。
英文版不是「名片頁」，而是**整個網站都有英文版**：首頁、認識學會、活動（含每個活動頁）、
慢活專欄（含每篇文章）、與我們合作、加入我們、理監事、聯絡我們、理監事專區說明、選單、頁尾、404。

未來可能會加更多語言（日文、韓文等），所以架構要做成「多語言」，**現在只開放繁體中文＋英文**。

## 2. 目標

1. 每個中文頁面都有對應的英文頁面，網址是在前面加 `/en`：`/about` → `/en/about`、
   `/column/tea-tree-february` → `/en/column/tea-tree-february`（**代稱沿用中文版的，不另取英文代稱**）。
   首頁是 `/en`。
2. 右上角語言切換：**地球圖示＋下拉選單**（示意頁 `/lang-mockup` 的方案 E）。
   - 電腦版顯示「🌐 中文 ▾」／「🌐 English ▾」，手機版只顯示地球圖示（放在漢堡選單旁邊，不收進選單）。
   - 下拉清單裡每種語言用自己的文字寫：繁體中文、English。目前語言打勾。
   - 選了之後跳到**同一頁**的另一個語言版本，而不是回首頁；連 `?type=`、`#錨點` 也一起帶過去。
3. 加新語言時，不必重做後台或每一頁：在一份語言清單裡多加一行，再補翻譯和介面文字即可。
4. 英文內容可在後台（Sanity Studio）由同仁檢視、修改。

## 3. 翻譯流程（使用者決定的）

- **不接任何自動翻譯服務、不產生新月費。** 翻譯由 Claude 在 Claude Code 對話裡完成，
  再用 `studio/migrations/` 的腳本寫進後台。
- 第一次：Claude 把現有全部內容翻成英文寫進後台。
- 之後：同仁新增或修改中文內容後，跟 Claude 說「幫我把新文章翻成英文」，Claude 翻好寫進後台，同仁看過、修改、發布。
- **還沒被同仁校對的翻譯照樣顯示在英文網站上**（有總比沒有好）。
- 後台每種語言有一個「已校對」勾選，讓人知道哪些還沒看過。只在後台出現，網站上不顯示。
- **翻譯寫進後台就直接上線**（寫入已發布的文件，觸發網站重建），不必等同仁按發布；
  同仁之後看過、修改、按發布，再勾「已校對」。
- **還沒有翻譯的內容**：英文網站上顯示中文內容，並在內容上方加一行提示，例如
  「English translation in progress — the original Chinese is shown below.」
- **列表裡還沒翻譯的項目**（首頁、活動列表、專欄列表、主題頁、側邊列表等）：照常列出、顯示中文標題，
  卡片上加一個小標籤（如「Translation in progress」），不隱藏、篩選與計數照舊。（Claude 的決定，延伸自上一條）

## 4. 非目標

- 現在不開放英文以外的語言（但架構要支援）。
- 不接 DeepL、Google 翻譯、Claude API、Sanity AI Assist 等自動翻譯服務。
- 不依瀏覽器語言自動導向英文版（交流時常是台灣人拿手機打開給外國人看，自動跳轉反而亂）。
- 不另外做英文網址代稱。
- 「從臉書貼文匯入」只處理中文，不動。
- 中文版的版面、網址、內容不做任何改動。

## 5. 絕對不能發生（反目標）

- **中文網站壞掉或任何既有網址失效**——這是正在上線中的網站。
- 英文頁面上中英混雜卻沒有提示，讓外國人以為網站壞了。
- 頁首因為語言切換變擠、跑版（尤其手機版）。
- 任何內部資料因為這次改動而公開（見 CLAUDE.md「公開／私密的分界線」）；`/en/board-area` 一樣 `noindex`、一樣只放說明。

## 6. 限制

- 技術架構沿用：Astro 靜態輸出、Cloudflare Workers、Sanity（私有 dataset）。不要提新架構。
- 學會同仁不碰程式；後台欄位名稱與說明一律中文。
- 不提供任意檔案上傳欄位，只給圖片（既有規則）。
- 每頁的 `<div class="page" id="page-XXX">` 要保留；英文頁沿用同一個 id，樣式才會套到。
- 新增樣式用 `site.css` 的變數，不寫死色碼。
- Logo 圖檔不得修改。
- 推上 main、`sanity deploy`、執行會寫入正式資料的搬移腳本，**都要等使用者說「推上去」**（或同義詞）才做。
- 學會英文名稱：**Slow Living Education Society of Taiwan**（以 logo 為準；JSON-LD 的 alternateName 可保留舊名）。

## 7. 已決定的作法

### 7.1 後台資料結構（Claude 的決定）

**中文欄位一個都不動、不搬資料。** 每一種要翻譯的文件（含單例頁面）新增一個 `translations` 物件欄位，
底下每個語言一個子物件，內容是「這份文件需要翻譯的欄位」的同名複本，外加 `reviewed`（已校對，布林值）：

```
translations: {
  en: { title, excerpt, body, ..., reviewed }
  // 之後：ja: {...}
}
```

- 語言清單集中在一處（例如 `studio/schemaTypes/shared.ts` 的 `LANGUAGES`，前端也需要同一份清單，
  做法比照 `src/lib/column.ts` 與 `shared.ts` 保持一致的現行方式）。`translations` 的子物件依這份清單產生。
- Studio 裡每種語言是文件上的一個分頁（group），標題如「English 英文版」，同仁切過去就能逐欄修改。
  每個英文欄位的說明文字要附上中文原欄位的名稱，方便對照。
- 為什麼不用欄位層級的多語陣列（internationalized-array）或文件層級的翻譯（document-internationalization）：
  兩者都要改寫所有既有欄位或複製文件，等於重搬整個正式資料庫，對上線中的網站風險太高。
  現在這個做法只「新增」欄位，中文版查詢完全不受影響。
- 只翻「文字」：標題、摘要、內文、說明、按鈕文字、圖片的 alt 與 caption、連結顯示文字、日期說明文字（如 `dateLabel`）等。
  圖片本身、網址、日期值、分類值、排序、報名狀態等不複製，英文版直接用中文版的。
  哪些欄位要翻，由實作者逐一 schema 判斷，原則就是「讀者看得到的文字」。
- 要翻的文件：`siteSettings`、`navigation`、`homePage`、`themesSection`、`aboutPage`、`joinPage`、`partnerPage`、
  `eventsPage`、`columnPage`、`donatePage`、`contactPage`、`boardAreaPage`、`article`、`author`、`person`、`event`、`activityType`。
  `plansPage`／`planItem` 已不顯示，不翻。

### 7.2 理監事姓名（Claude 的決定）

`person` 的英文版多一個「英文姓名」欄位，**預設留空**，空的時候英文頁顯示中文姓名。
Claude 第一次翻譯時**不要自行替人取英文名或音譯**——那是本人的決定。職稱、群組名（理事、監事…）照常翻譯。
作者（`author`）同理。

### 7.3 前端

- 英文頁面放在 `src/pages/en/` 底下，但**不要把每一頁複製一份**：頁面內容抽成共用元件／共用函式，
  中文頁與英文頁都呼叫它，只差傳入的語言。
- 取資料：在查詢層把翻譯合併好再交給頁面，頁面不需要知道是哪個語言的資料。
  合併規則以「整份文件」判斷是否已翻譯：該語言的 `translations` 沒有內容 → 整份顯示中文＋「翻譯中」提示；
  有內容 → 以英文為主，個別英文欄位空著的就退回中文（這種情況不另外提示）。
- `html lang`：英文頁 `en`，中文頁維持 `zh-Hant-TW`。
- SEO：每頁輸出 `<link rel="alternate" hreflang>`（zh-Hant、en、x-default 指向中文），canonical 各指向自己；
  sitemap 一併列出英文頁；英文頁的 `og:locale`、JSON-LD 也要是英文。
  **還沒翻譯、整頁顯示中文的英文頁**：`noindex`，且不列入 sitemap 與 hreflang，翻好後自動恢復。（Claude 的決定：避免 Google 把中文頁當成英文版）
- 介面上固定的小字（「首頁」麵包屑、「閱讀全文」、「報名狀態」標籤、分類名、系列名、日期格式、「照片待補」等）
  目前有一部分寫死在 .astro 裡：**改用一份介面文字字典，按語言查**。分類／系列的英文名稱要和後台 `shared.ts` 保持一致。
  這些字典裡的英文由 Claude 翻譯（Claude 的決定：這類字放程式裡，因為同仁不會改，也不是內容）。
- 語言切換鈕：新元件，放在 `Header.astro` 的 `header-actions` 裡、「探索活動」按鈕旁。
  下拉要能用鍵盤操作、點外面會關、手機上點得到（至少 44px）。
- 中文頁面的連結維持現狀；英文頁面裡的站內連結（包括後台填的選單網址，如 `/about`）要自動加上 `/en`，
  外部連結不動。

### 7.4 翻譯腳本

- 放在 `studio/migrations/`，用 `npx sanity exec <檔案> --with-user-token` 執行（既有慣例）。
- 第一次翻譯和之後的單篇翻譯都走這條路：Claude 先在本機產生英文內容，給使用者在本機預覽，
  使用者同意後才寫入正式資料。
- 預覽不寫正式資料（Claude 的決定）：腳本先把英文內容存成本機檔案，本機建置時合併進來給使用者預覽；
  使用者同意後才把同一份內容寫進後台。本機檔案放 `_private/` 或其他 gitignore 的位置，不進 git。
- 只 patch `translations.<語言>` 這個欄位，**已發布版本和既有草稿都要寫**（草稿若存在），
  這樣同仁之後發布舊草稿時不會把翻譯洗掉，也不會把同仁未完成的中文修改一起發布。
- 每個語言子物件存一個「翻譯時的中文版本指紋」（例如所有被翻欄位的中文內容雜湊）。
  之後中文被改過，指紋對不上，就代表英文可能過時：Studio 在英文分頁顯示提醒，
  Claude 被問「還有哪些要翻」時也用它來列出「新的」與「中文改過的」。網站照常顯示舊英文，不另提示。（Claude 的決定）
- 寫入時 `reviewed` 一律設為 false；**不要覆蓋已經 `reviewed: true` 的翻譯**，除非使用者明確要求。
- 寫入已發布文件時要處理「該文件同時有未發布草稿」的情況，不能把同仁的草稿蓋掉或把草稿內容意外發布。

### 7.5 文件更新

- `docs/同事操作手冊.md`：加入「幫我把○○翻成英文」的說法、英文分頁在後台哪裡、「已校對」怎麼用。
- `CLAUDE.md`：檔案結構、同仁說法對照表、「內容都在後台」一節補上翻譯規則。

## 8. 留給實作者決定

- 共用元件／路由的具體拆法（例如動態 `[...lang]` 路由或 `src/pages/en/` 下的薄殼頁）。
- 介面文字字典的檔案位置與格式。
- 下拉選單的細部樣式（以 `/lang-mockup` 方案 E 為準，配色用既有變數）。
- 「翻譯中」提示的確切英文字句與樣式。
- Studio 裡是否在文件列表顯示「英文未翻／未校對」的小標記（有的話很好，非必要）。
- 是否使用 Astro 內建 i18n 路由設定。

## 9. 上線順序（Claude 的決定）

第一輪全站翻譯**包含在這次工作裡**：先做好前端與後台欄位、Claude 翻完全部現有內容、使用者在本機預覽，
使用者說「推上去」時網站、後台欄位、翻譯一起上線，上線當天英文版就是完整的。

## 10. 驗收

- 中文網站每個既有網址的輸出與改動前一致（建置後比對 `dist/` 的中文頁面，不應有內容差異，除了新增的切換鈕與 hreflang）。
- 每個中文頁都有對應 `/en/...` 頁面，切換鈕來回切換都停在同一頁。
- 刻意清空某篇文章的英文翻譯 → 英文頁顯示中文＋「翻譯中」提示、該頁 noindex 且不在 sitemap、列表卡片出現「翻譯中」小標籤。
- 改動某篇已翻譯文章的中文 → Studio 英文分頁出現「中文已更新」提醒。
- 手機寬度（375px）頁首不跑版。
- `/en/board-area` 有 noindex 且不在 sitemap。
- `npm run build` 通過；`studio` 的 `npm run test:structure` 通過。
- 完成後刪除示意頁 `src/pages/lang-mockup.astro`。
