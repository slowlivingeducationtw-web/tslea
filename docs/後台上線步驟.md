## 步驟

### 1. 登入 Sanity

```bash
cd studio
npx sanity login
```

瀏覽器會開起來，用**學會的 Google 帳號**登入（跟建專案時同一個）。

### 2. 確認 dataset 存在且為私有

```bash
npx sanity dataset list
```

應該要看到 `production`。沒有的話：

```bash
npx sanity dataset create production --visibility private
```

已經存在但是公開的話：

```bash
npx sanity dataset visibility set production private
```

> ⚠️ **這一步很重要。** 公開的 dataset 代表未發布的草稿可以被匿名 API 讀走。
> Growth Trial 期間可以設私有；掉回免費方案就只能公開。

### 3. 匯入內容

```bash
npx sanity dataset import ../scripts/out/content.ndjson production
```

會匯入 48 筆文件，並自動從正式站抓 5 張圖片。跑完它會顯示匯入統計。

> 想重跑的話加 `--replace`，會覆蓋同 `_id` 的文件。

### 4. 在本機看看後台

```bash
npx sanity dev
```

打開 http://localhost:3333 —— **這是同事將來會看到的畫面**。

請特別檢查：
- 左側選單是不是「內容 / 組織 / 頁面文案 / 網站設定」四組
- 介面是不是繁體中文
- 點進「專欄文章」→ 茶樹那篇，內文的分行有沒有保留
- 點進「捐款支持」，銀行與帳號欄位下方的**勸募許可提醒**看不看得到
- 隨便找個地方試試看，**確認找不到任何可以上傳 PDF 或 Excel 的欄位**（這是刻意的）

### 5. 部署後台

```bash
npx sanity deploy
```

會問你 studio hostname，設定檔裡已經填好 `tslea`，直接確認即可。
完成後後台就在 **https://tslea.sanity.studio**，要登入才進得去。

## 日常維護需要知道的

**同事改內容 → 按發布 → 約 90 秒後網站更新。** 中間不需要任何人做事。

**環境變數**：Cloudflare Workers 的 `tslea` 專案有一個 `SANITY_READ_TOKEN`，必須是「**祕密**」不是「變數」（設成變數的話，值會明碼顯示在後台）。它是 viewer 權限，只能讀不能寫。少了它，建置會失敗，網站會停在上一個成功的版本。

**token 換發**：
```bash
cd studio
npx sanity tokens list            # 看現有的
npx sanity tokens create "名稱" --role viewer -y --json
npx sanity tokens delete <id> -y  # 刪掉舊的
```
換完記得同步更新 Cloudflare 的祕密，否則下次建置會失敗。

**webhook**：名稱 `cloudflare-rebuild`，`npx sanity hooks list` 可查、`hooks logs` 可看每次觸發的結果。`includeDrafts: false`，所以**存草稿不會觸發重建，只有按「發布」才會**。
